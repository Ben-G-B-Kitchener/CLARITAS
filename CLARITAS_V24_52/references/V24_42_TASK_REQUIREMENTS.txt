5. FALSE NEGATIVE #1: SMITH LAMBDA REFERENCE PRECISION
======================================================================

The V24.41.1 Smith-Lambda GPU implementation appears numerically correct.

The validator nevertheless reports:

    smith_lambda_pass = false

for a small number of cases.

The cause is that the CPU reference and GPU test are not using numerically identical alpha inputs.

The CUDA test is supplied a float32 roughness alpha equivalent to:

    alpha = np.float32(tan(25 degrees))

while the independent CPU reference uses the unquantized double-precision:

    tan(25 degrees)

This input mismatch is larger than the deliberately tight Lambda comparison tolerance.

Representative measured example:

    c = +0.1

    CUDA:
        approximately 0.8691697500903656

    current CPU reference:
        approximately 0.8691697186797003

    apparent difference:
        approximately 3.14e-8

But recomputing the independent CPU reference using the ACTUAL float32 alpha supplied to CUDA gives approximately:

        0.8691697500903656

which agrees essentially exactly.

Therefore:

    DO NOT LOOSEN THE LAMBDA TOLERANCE.

Instead make the CPU reference use precisely the same quantized input value that the CUDA kernel actually receives.

The test must compare:

    same physical input
    different independent numerical implementations

not:

    slightly different physical inputs
    with an artificially relaxed tolerance.

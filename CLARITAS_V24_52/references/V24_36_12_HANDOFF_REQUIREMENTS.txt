BUG 1 — PROBABILITY CLOSURE DOUBLE COUNT

The summarizer effectively used:

        entry_reflection_count
      + escaped_count
      + absorbed_count
      + numerical_failure_count
      + censored_count

But:

    escaped_count

already includes entry-reflection histories.

Therefore entry reflections were counted twice.

Observed evidence:

    probability_count_closure_abs_max = 2925

and that exactly matched the maximum entry_reflection_count.

Correct closure is:

    escaped_count
  + absorbed_count
  + numerical_failure_count
  + censored_count
  == samples

The underlying GPU data showed exact closure when counted correctly.

Fix this.

Retain a permanent regression that would fail if entry reflections are
double-counted again.

----------------------------------------------------------------------
BUG 2 — WRONG REFRACTIVE-INDEX ORDER IN REVERSE REFLECTION TEST
----------------------------------------------------------------------

The CUDA fixed-microfacet reverse Fresnel audit incorrectly used swapped
refractive indices for reflection:

    fresnel_R_complex(co, N2, 0, N1, 0)

For a reflected ray, the ray remains in the incident medium.

Therefore the reversed reflection-side Fresnel evaluation should use the
same medium pair orientation appropriate to reflection, not the
transmission reverse convention.

This produced the spurious:

    reflection_grazing
    fresnel_reverse_abs ~= 0.004779819

while direction reversibility and independent CPU/BSDF reference tests
were already effectively exact.

Fix the audit.

Retain reflection and transmission reverse tests separately so this
mistake cannot recur.

4. PRIMARY NUMERICAL DEFECT TO VERIFY
======================================================================

The current diagnosis is that the V24.39 signed Beckmann VNDF implementation contains a truncated negative-tail inverse-CDF construction.

Inspect the actual source before modifying it.

Look specifically for logic equivalent to:

    float erf_min = -0.9999f;

    float erf_max = fmaxf(erf_min, erff(slope_i));

and later:

    *slope_x = erfinvf(ex);

The problem is potentially fundamental to the numerical support of the signed sampler.

Because approximately:

    erfinv(-0.9999) ~= -2.751064

this creates a hard minimum possible sampled slope of approximately:

    slope_x >= -2.751064

For sufficiently deep backside incidence, the physically required visible-slope support can lie beyond that artificial truncation.

The visibility condition for a representative Beckmann slope orientation is of the form:

    slope_x < cot(theta)

and around:

    theta ~= 160 degrees

cot(theta) becomes more negative than the artificial -2.751 tail limit.

Therefore the sampler can reach an angular regime where no generated slope can satisfy the subsequently enforced visibility condition.

This can cause valid deep-backside states to be incorrectly reported as numerical failures.

YOU MUST VERIFY THIS AGAINST THE ACTUAL V24.39 CODE AND ITS COORDINATE/SCALING CONVENTIONS.

Do not blindly assume these approximate analytical numbers are exact for every transformed coordinate.

But treat this as the primary defect hypothesis.

5. SECOND NUMERICAL DEFECT TO VERIFY
======================================================================

Inspect the projected-area / normalization expression used by the signed Beckmann VNDF.

    0.5f * (erff(a) + 1.0f) * cos_theta
